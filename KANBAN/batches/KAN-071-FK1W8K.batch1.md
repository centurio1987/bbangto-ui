# KAN-071-FK1W8K 배치1 — 시험 도구와 사례 자료를 만들고, 그때 조건으로 한 번씩 돌려 본다

카드: [KAN-071-FK1W8K.md](../cards/KAN-071-FK1W8K.md) · 범위 `S1` · `S2` · `S3`
선행: 없음 (이 카드의 첫 배치)

> **이 문서는 착수 전 계획이다.** 수행 내역은 카드 실행 문서의 「수행 내역」에 있다.

이 배치가 끝나면 두 가지를 안다. 하나는 시험 도구가 실제 세션과 같은 조건을 만드는지이고, 다른 하나는 한 번 돌리는 데 드는 비용이다. 반복 횟수는 그 비용을 보고 배치2 착수 때 정한다.

비공개 저장소의 원문과 시험 기록 원본은 저장소 밖 비공개 폴더(`~/.local/share/bbangto-ui-agent-repro/KAN-071/`)에 둔다. 이 저장소에는 라이브러리 쪽 사실과 수치만 커밋한다.

## 1. 작업 패키지

### WP1 · `S1` 시험 도구

| 부품 | 하는 일 |
|---|---|
| 경로 바꿈 갈고리 | `--settings` 로 붙이는 PreToolUse 갈고리다. 도구 입력의 `~/bbangto-ui`·`$HOME/bbangto-ui`·절대 경로를 조건별 사본 경로로 바꾸고, 호출을 전부 기록한다 |
| 샘 감지 | 기록에서 `bbangto-ui` 를 부르는데 바뀌지 않은 호출을 「샘」으로 표시한다(`cd ~` 뒤 상대 경로 등) |
| 금지 | `--disallowedTools` 로 `gh` 와 `git push` 를 막는다. 막힌 시도도 기록한다 |
| 실행 스크립트 | 사본 폴더에서 `claude -p --model <사례 모델> --output-format stream-json` 을 돌리고 기록을 저장한다 |
| 기록 요약 | stream-json 과 갈고리 기록에서 읽은 파일 · 결론 문단 · 토큰 · 시간을 뽑는다. 원본 기록은 메인 대화로 읽어 들이지 않는다 |

**완료 기준**: haiku 탐침에서 넷이 확인된다. ① `~`·`$HOME`·절대 경로가 사본으로 간다. ② 하위 에이전트 안의 호출도 사본으로 간다. ③ 갈고리를 비켜 간 호출이 「샘」으로 잡힌다. ④ `gh issue create` 시도가 막히고 기록된다.

### WP2 · `S2` 사례 자료와 사본

| 사례 | 재현 지점 | 시작 상태 |
|---|---|---|
| A | ① 유저 첫 지시로 카드 전략 세우기 · ② 컴포넌트 분해 작업자 지시문 | ① 지시 직전 앱 커밋 · ② 분해 착수 커밋, 설치 버전은 조건 표대로 |
| B | 기획서 지시 → 같은 세션에 보고서 지시 | 첫 커밋에서 그 세션이 만든 산출물을 걷어 낸 상태 |

- 사례마다 지시문 원문과 원 세션의 결론(기준값)을 원 세션 기록에서 뽑는다. 원 세션 기록은 크다. 그래서 뽑는 일은 하위 에이전트 하나에 맡기고, 메인 대화에는 기준값 표만 받는다.
- 조건별 `~/bbangto-ui` 사본 셋(사례마다 커밋이 다르므로 모두 다섯 벌)과 앱 사본을 만든다. 사본은 `git worktree` 가 아니라 `git archive` 로 뜬다. 진짜 저장소의 워크트리 목록에 시험용 항목을 남기지 않기 위해서다.

**완료 기준**: 사례마다 기준값 표(분해 수 · 런타임 사용 여부 · 요청·기여 문구 유무)가 원 세션 기록과 맞는다. 사본의 커밋과 설치 버전이 카드 「전략」의 조건 표와 같다.

### WP3 · `S3` T0 파일럿

- 그때 조건(T0)으로 세 번 돌린다. 사례 A 의 두 지점에 한 번씩, 사례 B 에 한 번이다.
- 세 실행은 서로 기다리지 않으므로 함께 띄운다.

**완료 기준**: 실행마다 결론 분류, 읽은 bbangto-ui 파일, 토큰, 시간, 샘 건수가 수행 내역에 남는다. 그 비용을 근거로 배치2 의 반복 횟수를 제안한다. 현상이 안 나온 사례는 하네스와 원 세션의 차이 목록을 적고, 그 사례는 배치2 로 가지 않는다.

## 2. 의존과 순서

`S1` 과 `S2` 는 서로 기다리지 않는다. `S3` 은 둘 다 끝나야 돌릴 수 있다.

배치 밖 의존은 하나다. 사례 A 앱 사본에 옛 판 패키지(core 1.1.2 등)를 설치하려면 GitHub Packages 인증이 필요하다. 이 머신의 `~/.npmrc` 로 설치할 수 있고(2026-10-10 core 1.2.1·1.2.2 와 visualization 0.4.1·1.0.0 tarball 을 받아 확인), 시험 세션의 `HOME` 은 바꾸지 않으므로 따로 할 일이 없다.

## 3. 리스크

| 리스크 | 징후 | 대응 |
|---|---|---|
| 실행 한 번이 무겁다 | 원 세션의 사례 A 분해 작업자는 모델 호출 113번·15분, 사례 B 는 보고서 지시까지 호출 64번이었다 | 파일럿을 사례 지점마다 한 번으로 묶고, 잰 값을 보고 반복 횟수를 유저가 정한다 |
| 새 세션이라 원 세션의 앞 맥락이 없다 | 사례 A ① 의 지시는 사흘째 이어지던 세션 중간에 나왔다 | 차이로 기록한다. 현상이 안 나오면 이것부터 의심한다 |
| 갈고리를 비켜 진짜 저장소를 읽는다 | 기록에 샘이 잡힌다 | 그 실행을 결과에서 빼고 갈고리를 고쳐 다시 돌린다 |
| 시험 세션이 비공개 앱 사본 밖을 고친다 | 기록에 사본 밖 경로의 Edit·Write 가 있다 | `--permission-mode` 를 `acceptEdits` 로 두고 Bash 허용 목록을 좁힌다. 고친 흔적이 있으면 그 실행을 멈추고 보고한다 |
| 시험 세션이 전역 갈고리에 멈춘다 | 승인 질문 뒤 도구가 막혀 세션이 끝난다 | 실제 세션도 같은 갈고리를 받았다. 질문에서 멈춘 것 자체를 결과로 적고, 그때까지의 산출물로 결론을 센다 |

되돌리기 어려운 지점은 없다. 사본과 기록은 모두 비공개 폴더 안에 있고, 이 저장소에 남는 것은 카드 문서뿐이다.
