# KAN-066-T6NR80 배치1 — build 없이 typecheck·test:unit 이 돌게 한다

카드: [KAN-066-T6NR80.md](../cards/KAN-066-T6NR80.md) · 범위 `S1` · `S2` · `S3`
선행: 없음 (이 카드의 첫 배치)

> **이 문서는 착수 전 계획이다.** 수행 내역은 카드 실행 문서의 「수행 내역」에 있다.

카드 목표가 이 배치에서 선다. 배치가 끝나면 dist 를 지운 워크트리에서 `pnpm typecheck`·`pnpm test:unit` 이 초록이다. 고치는 것은 설정 파일과 게이트 테스트이고, 라이브러리 소스는 건드리지 않는다.

## 1. 작업 패키지

### WP1 · `S1` 조건 누락 게이트와 소스 조건

| 파일 | 하는 일 |
|---|---|
| `packages/foundations/src/workspaceSource.ts` | 워크스페이스 패키지의 `package.json` 을 받아 위반을 내는 순수 함수. exports 의 진입점 가운데 `import` 가 `.js` 인 것마다 `bbangto-source` 조건이 **맨 앞**에 있고, 그 값이 실제로 있는 `src/…ts` 인지 본다. JSON·manifest 진입점은 대상이 아니다 |
| `packages/foundations/src/workspaceSource.test.ts` | 실제 저장소 검사 1건(먼저 빨강) + 실패 주입: 조건 없음 · 조건이 `types` 뒤에 있음 · 가리키는 파일 없음 |
| `packages/*/package.json` 7개 | 진입점 9개(`.` ×7 · foundations `./meta` · visualization `./type-meta`)에 조건을 맨 앞에 붙인다 |
| `tsconfig.json`(루트) | `"customConditions": ["bbangto-source"]` |

**완료 기준**: 게이트가 먼저 빨강이었다가 초록이 된다. dist 를 지운 상태에서 `pnpm typecheck` 가 초록이다.

### WP2 · `S2` vitest 가 소스를 찾게

| 파일 | 하는 일 |
|---|---|
| `packages/{hooks,visualization,style-guide-catalog,visualization-style-guide-catalog}/vitest.config.ts` | `resolve.conditions` 에 `bbangto-source` 를 Vite 기본 조건과 함께 넣는다 |
| `packages/foundations/vitest.config.ts`(새로 만듦) | 위와 같은 조건. S3 에서 크기 게이트를 빼는 자리도 이 파일이다 |

다섯 곳이 같은 조건 목록을 쓰므로 한 곳에서 가져다 쓸지는 손댈 때 정한다(루트 공용 파일 하나 대 줄 복사).

**완료 기준**: dist 없이 test:unit 에서 크기 게이트를 뺀 나머지가 모두 초록이다. hooks(jsdom·react)도 초록이어야 한다.

### WP3 · `S3` 크기 게이트를 build 끝으로

| 파일 | 하는 일 |
|---|---|
| `packages/foundations/vitest.config.ts` | 기본 실행에서 `bundleBudget.test.ts` 를 뺀다 |
| `packages/foundations/vitest.bundle.config.ts`(새로 만듦) | 크기 게이트 하나만 도는 설정 |
| `packages/foundations/package.json` | `test:bundle` 스크립트 |
| `package.json`(루트) | `build` 끝에 foundations `test:bundle` 을 잇는다 |

**완료 기준**: dist 없이 `pnpm test:unit` 이 초록이다. `pnpm build` 출력 끝에서 크기 게이트가 돈다. 한 패키지의 basis·max 를 규칙대로 작게 고치면 build 가 실패하고, 되돌리면 통과한다.

## 2. 의존과 순서

`S1 → S2` 순서다. vitest 조건은 package.json 에 조건이 있어야 뜻이 있다. `S3` 은 S1·S2 와 다른 일이지만 foundations vitest 설정을 S2 와 함께 고치므로 S2 뒤에 둔다.

배치 밖 의존은 없다. 이 배치는 dist 를 지운 상태에서 시작한다(착수 전 실험 뒤 지웠다).

## 3. 리스크

| 리스크 | 징후 | 대응 |
|---|---|---|
| `resolve.conditions` 가 Vite 기본 조건을 덮는다 | hooks 에서 react 를 못 찾거나 다른 빌드를 집는다 | Vite 가 내보내는 기본 조건 목록을 펼쳐 함께 넣는다. 안 되면 `ssr.resolve.conditions` 쪽으로 옮긴다(착수 전 실험은 둘 다 넣었다) |
| 소스를 읽는 typecheck 가 다른 패키지의 엄격 옵션 위반을 끌어온다 | 고치지 않은 패키지에서 새 오류 | 착수 전 실험(tokens·core·visualization)에서는 0건이었다. 나오면 그 패키지 소스를 고치지 않고 원인을 수행 내역에 남긴 뒤 유저에게 묻는다 |
| build 가 크기 초과로 실패하면 Storybook 용 dist 갱신까지 막힌 것처럼 보인다 | `pnpm build` rc≠0 | dist 는 이미 다 만들어진 뒤라 Storybook 은 돈다. CLAUDE.md 설명에 그 사실을 적는다(S5) |

되돌리기 어려운 지점은 없다. work 마다 `kan/KAN-066-T6NR80/S<n>` 태그를 단다.
