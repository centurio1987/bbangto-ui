집필은 배치 2에서 시작한다. 이 배치는 **집필 워커 4개가 각자 조사하지 않도록** 사실과 축을 먼저 못박는 자리다. 안 하면 워커마다 다른 수치를 쓰고, 통합하는 S6에서 그 차이를 다시 대조해야 한다.

## 1. 작업 패키지

### WP1 · `S1` 사실 수집 — export · 매니페스트 실측 · 죽은 스니펫

패키지 8종의 **공개 export**를 배럴(`src/index.ts`)에서 실제로 읽고, 매니페스트 4종의 엔트리 수를 세고, 현 README 코드 블록의 import를 그 목록과 대조한다.

- 대상 배럴: `packages/{core,tokens,foundations,hooks,style-guide-catalog,visualization,visualization-style-guide-catalog}/src/index.ts`
- 대상 매니페스트: `catalog.manifest.json`(UI·viz), `foundation.manifest.json`, `type.manifest.json`
- 대조 대상: 현 README의 코드 블록 7개

**완료 기준**: `scratchpad/S1-facts.md` 에 ① 패키지별 export 목록 ② 매니페스트 4종 실측 수치 ③ 현 README import 토큰마다 `살아있음`/`죽음`(+대체 export) 판정이 표로 남는다. 판정 근거는 전부 파일 경로로 건다.

### WP2 · `S2` 사례 축 확정 — 8종의 경계와 매핑

전략의 사례 후보 8종을 확정한다. 후보를 그대로 쓰지 않고 S1 실측에 비춰 **합치거나 쪼갠다** — 예를 들어 hooks가 30개뿐이면 독립 사례가 아니라 사례 1의 하위 절이 맞을 수 있다.

**완료 기준**: `scratchpad/S2-cases.md` 에 사례마다 (사례 이름 · 누가 언제 · 필요한 패키지 · 최소 코드가 화면에 내는 것 · 다음 사례 링크 · 담당 워커 번호)가 채워진 표가 나온다. 사례 간 중복 0, 패키지 8종 중 어느 사례에도 안 걸린 것 0.

### WP3 · `S3` authoring-kit 준비 — spec 등록 · voice 선정

authoring-kit은 이 프로젝트에 **미설치**다(`~/.claude/plugins/installed_plugins.json`에 bbangto-ui 항목 없음). 설치는 `~/.claude` 공유 상태 변경이므로 하지 않고, 마켓플레이스 경로의 스크립트를 `CLAUDE_PLUGIN_ROOT`로 직접 부른다.

```
CLAUDE_PLUGIN_ROOT=~/.claude/plugins/marketplaces/centurio87-plugins/plugins/authoring-kit \
  python3 $CLAUDE_PLUGIN_ROOT/scripts/authoring.py status
```

- spec `bbangto-readme` 를 `.claude/authoring/specs/` 에 새로 등록한다 (`authoring-spec` SKILL.md + `SPEC_SCHEMA.md` 규격).
- voice는 사용자 레지스트리의 5종(`ppangto`·`ppangtolab-prof`·`ppangtolab-researcher`·`ppangtolab-teacher`·`yundeok`) 중에서 고른다. 절차 문서이므로 `ppangtolab-teacher`가 1순위 후보 — **최종 선정은 검토 판단 항목으로 낸다**.
- `paths.json` 에 README 출력 경로를 적는다.

**완료 기준**: `authoring.py status` 의 `specs` 에 `bbangto-readme` 가 뜨고, `authoring.py validate` 가 갈래(axis) 위반 0으로 통과한다.
