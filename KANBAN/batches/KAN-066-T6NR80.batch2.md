### WP2 · `S5` 배포물 확인과 문서 정리

배포물 확인:
- build 뒤 dist JS 에서 `@centurio1987/*` 가 외부 import 로 남고, 다른 패키지의 `/src/` 를 끌어온 줄이 0건이다.
- `.d.ts` 가 다른 패키지 타입을 외부 import 로 둔다(core · visualization-style-guide-catalog).
- `npm pack --dry-run` 목록을 main 빌드와 견준다. dist 밖 파일이 같고 dist 파일 수가 같다.

문서 정리:

| 자리 | 고치는 것 |
|---|---|
| `CLAUDE.md` 게이트 설명(35·39·102·105줄 부근) | build 줄에 「끝에서 번들 크기 게이트」, test:unit 줄에서 「번들 크기」를 빼고 「소스를 읽으므로 build 없이 돈다」 |
| `QUALITY_CHECKLIST.md` test:unit 줄 3곳 | 위와 같은 내용 |
| `.github/workflows/release.yml` | 「Unit gates (bundle size included)」 단계 이름. 크기 게이트는 Build 단계에서 돈다 |
| `bundle-budget.json` `$comment` · `bundleBudget.test.ts` 머리 주석 | 「`pnpm build` 뒤 `pnpm test:unit` 에서 돈다」 → 「`pnpm build` 끝에서 돈다」 |
| 메모리 `fresh-worktree-gate-order` | 「새 워크트리는 typecheck 전에 build 를 먼저」를 걷는다. 셸 함정(zsh 낱말 분리 · `rm` 은 `bash -c` 밖에서)은 남긴다 |

**완료 기준**: 저장소에서 「build 를 먼저」 류 서술을 찾았을 때 남는 자리가 크기 게이트·Storybook 처럼 실제로 dist 를 읽는 곳뿐이다. 지나간 카드 문서·검토서(`KANBAN/`·`.kanban/`)는 그때의 기록이라 고치지 않는다.

### WP3 · `S6` 게이트 5종과 새 워크트리 재현

1. dist 를 모두 지우고 `pnpm typecheck` → `pnpm test:unit` 이 build 없이 초록이다.
2. 이어서 CLAUDE.md 순서대로 게이트 5종: `pnpm typecheck` · `pnpm build`(끝에서 크기 게이트) · `pnpm test` · `pnpm --filter storybook build` · `pnpm test:unit`.

**완료 기준**: 1·2 모두 초록이고 결과를 수행 내역에 남긴다.

| tsx 가 Node 의 `--conditions` 를 넘기지 않는다 | 생성기가 여전히 dist 를 찾다 실패 | 확인 안 함. 안 되면 `NODE_OPTIONS=--conditions=bbangto-source` 로 넘긴다 |
