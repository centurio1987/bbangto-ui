### WP2 · `S2` 계산에 `on.ink` 잇기

- `packages/tokens/src/visualization.ts`: `on` 에 선택 칸 `ink?: string` 을 더한다. JSDoc 에 동작(면마다 4.5:1 을 넘으면 계산 후보보다 먼저), 우선순위(면별 덮어쓰기 > `ink` > 계산 후보 넷), 대비는 계산이 지킨다는 것, 문장에 이름 색을 적으면 카탈로그 시험 표에도 넣는다는 것을 쓴다.
- `packages/visualization/src/tokens/onInk.ts`: `pickOnInk` 후보 맨 앞에 `f.on?.ink` 를 둔다. 머리 주석의 후보 설명을 고친다.

**완료 기준**: WP1 viz 시험 초록, `pnpm typecheck` 초록. 카탈로그 시험 ②는 여전히 빨갛다(가이드는 아직 칸을 안 쓴다).

### WP3 · `S3` 가이드 7개에 `on.ink` 적기

위 표대로 색 묶음 12개에 `on: { ink: … }` 를 적는다. 파일은 `artdecoLuxe.tsx`·`darkluxe.tsx`·`synthwave.tsx`·`hudTelemetry.tsx`·`risoPrint.tsx`·`colorfulFlat.tsx`·`bauhausGeometric.tsx` 다. darkluxe 의 `OXBLOOD_ON`(노드·C4 덮어쓰기 10개, KAN-069)은 지우고 `on: { ink: CREAM }` 으로 바꾼다. `makeVizColorway` 로 만든 색 묶음은 base 의 `on` 을 물려받으므로, base 에 적을 때는 다른 묶음이 함께 바뀌는지 잰다.

지침 문장 속 대비 수치(artdeco 「≥11:1」, synthwave 「≥10.6:1」, darkluxe 「≥13:1」, hud 「~18:1」 등)를 바뀐 그림으로 다시 재서 맞는지 수행 내역에 적는다. 틀린 수치가 있으면 수치만 고친다.

**완료 기준**: 카탈로그 `textInk.test.ts` 초록, `onInk.test.ts`(모든 면 4.5:1)·`accessibility.test.ts`(over-claim 0) 초록. 한 가이드의 `on.ink` 를 잠시 지우면 카탈로그 시험 ①②가, 계산에서 `on.ink` 를 빼면 스토리 검사가 빨개지고, 되돌리면 초록이다.

## 2. 의존과 순서

`S1 → S2 → S3` 순서다. S2 의 칸이 있어야 S3 이 적을 수 있다.

배치 밖 의존은 셋이다.

- KAN-069 가 main 에 병합된 뒤 워크트리를 만든다. KAN-069 가 `tagColor`·`c4.labelColor` 를 걷고 가이드 문장을 고친 상태가 이 계획의 기준이다. 병합 뒤 main 에서 위 표를 다시 재고, 숫자가 다르면 표와 카드 전략을 고친 뒤 착수한다(직렬 기록의 「전략 재수립」).
- 단위 시험과 `pnpm typecheck` 는 build 없이 돈다(KAN-066). 스토리 시험(`pnpm test`)은 `dist` 를 읽으므로 그 전에 `pnpm build` 를 돌린다.
- 워크트리 브랜치는 착수 직전에 main 을 다시 따라잡는다. 다른 세션이 main 에 칸반 커밋을 쌓는다.
