# KAN-054-M48FNQ 배치5 — DropdownMenu 닫힘을 맞추고 다시 검토로

## 1. 작업 패키지

### WP1 · `S10` DropdownMenu 닫힘

목록 쪽(`handleMenuKeyDown`의 Enter/Space, `handleMenuClick`)에서 닫던 것을 걷고, 항목이 실제로 실행될 때 내부 문맥으로 신호를 받아 닫는다. 외부가 항목 처리기에서 `preventDefault`하면 실행도 닫힘도 없다(1번 합성 규칙).

**완료 기준**: 「막으면 열린 채로, 안 막으면 닫힘」 스토리 빨강 → 초록, 기존 Menu 스토리·DropdownMenu 실제 입력 초록.

### WP2 · `S11` 마무리

changeset 보강, 게이트 5종, core 전체 포커스 표시 새 카드(백로그), 검토서 `review-init --refresh`와 §3-6 상세 정정(components 13개), 검토로 이동.

**완료 기준**: 게이트 5종 초록, 검토로 이동.

## 2. 의존과 순서

`S10 → S11`. S11의 게이트가 S10까지 덮는다.

## 3. 리스크

| 리스크 | 징후 | 대응 |
|---|---|---|
| 닫힘을 항목으로 옮기면 단독 Menu 항목도 닫힘 신호를 낸다 | 단독 Menu 스토리에서 오류 | 문맥은 DropdownMenu만 제공한다. 없으면 아무 일도 안 한다 |
| 새 카드 등록이 main 보드와 겹친다 | 카드 브랜치에서 추가한 카드가 병합 때 충돌 | 루트 카드는 main에서만 추가한다(브랜치 규율). 완료 처리 뒤 main에서 등록한다 |
