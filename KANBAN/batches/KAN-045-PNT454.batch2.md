## 1. 작업 패키지

work 둘(`S4`·`S5`)을 **사례 단위로 4워커에 나눈다.**

### WP1 · `S4` 사례 1~5 집필 — 워커 A · B

`S2` 확정 결과 사례가 **8종에서 10종으로 늘었다.** core 하나에 성질이 다른 세 덩이(부품 · 섹션 통짜 · 모션)가 들어 있어 한 사례로 묶으면 절차를 못 쓴다는 것이 이유다(`S2-cases.md` §0). 그래서 work 경계(`S4`=1~5, `S5`=6~10)와 워커 경계가 어긋난다 — 아래 표가 정본이다.

| 워커 | 사례 | 대상 |
|---|---|---|
| A | 1 앱에 컴포넌트를 얹는다 / 2 페이지 섹션을 통째로 / 3 움직임을 붙인다 | core (components 241+icon 107 / blocks 13+patterns 4 / motion 25+shader 10) |
| B | 4 브랜드 색으로 갈아입힌다 / 5 완성된 룩을 골라 입힌다 | foundations 76 · style-guide-catalog 51 |

**완료 기준**: 사례마다 `scratchpad/S4-case<n>.md` 에 (도입 2~3문장 · 번호 절차 · 코드 블록 · 「그다음」 링크)가 서고, **코드 블록의 모든 import 토큰이 `S1-facts.md` 의 export 목록에 있다.** 없는 토큰이 하나라도 있으면 그 WP는 미완이다.

### WP2 · `S5` 사례 6~10 집필 — 워커 B · C · D

| 워커 | 사례 | 대상 |
|---|---|---|
| B | 7 로직만 가져다 쓴다 | hooks 30 (peer는 react 하나) |
| C | 6 **룩을 직접 만든다(UI)** / 10 이 레포에 기여한다 | 저작 헬퍼 12종 · 대비 게이트 · 매니페스트 등재 · 품질 게이트 |
| D | 8 다이어그램·인포그래픽 / 9 **viz 룩을 직접 만든다** | visualization 유형 87 · viz 카탈로그 30 · viz 저작 헬퍼 5종 |

배정을 개수가 아니라 **무게**로 나눴다. 사례 6이 가장 무겁고(저작 헬퍼 12종 + 게이트 + 등재), 10은 그 등재 절차의 뒷부분이라 같은 사람이 써야 이어진다. 7은 가장 가벼워 B에 얹었다.

**완료 기준**: 위와 같음. 더해 **사례 6·9는 대비(WCAG) 게이트와 매니페스트 등재까지** 절차에 포함한다 — 그 둘이 없으면 저작한 룩이 CI를 통과하지 못한다.

### 워커 공통 계약

네 워커가 같은 형식으로 쓰게 만드는 것이 이 배치의 성패다. 오케스트레이터가 **모든 워커 프롬프트에 아래를 그대로 넣는다.**

1. **입력은 셋뿐** — `S1-facts.md`(사실) · `S2-cases.md`(갈래) · 선정된 voice 요약. 레포를 다시 조사하지 않는다. 다만 `S2-cases.md` §4 의 경고 7건(같은 이름 다른 패키지 21건 · preset 이름 규칙 반대 · Showcase 이름 유추 금지 · `foundationCatalog` 타입 비안전 · 매니페스트 갱신 4명령 분리 · 서브패스 전용 심볼 · 현 README 수치 금지)은 프롬프트에 그대로 싣는다.
2. **출력 형식 고정** — `### 사례 N · <이름>` → 도입 → `1.`~`n.` 번호 절차 → 코드 블록 → `**그다음**` 한 줄.
3. **수치는 `S1-facts.md` 것만 쓴다.** 세지 않은 수를 적지 않는다.
4. **파일을 쓰지 않는다** — scratchpad 산출물 한 개만 낸다. README는 S6이 조립한다.

**워커가 오케스트레이터를 정정한 것 2건** — 위임이 실제로 값한 자리다.
- C: 대비 over-claim 게이트 주체를 오케스트레이터가 "CI hard-fail" 이라 지시했으나 `.github/workflows/` 에는 `release.yml` 하나뿐이고 `install` + `build` 만 돈다. 게이트는 패키지 vitest 이고 사람이 `pnpm test:unit` 을 쳐야 돈다.
- D: viz 카탈로그 `prebuild` 위치가 `package.json:23`(S1 표의 `:19` 는 오기). 색 스킴 불변식의 집행 지점이 storybook 스토리 다섯 자리라 S1 게이트 표에 빠져 있었다.

**`S6` 이 처리할 것 3건**
1. 사례 제목·앵커 통일 — 정본은 `S2-cases.md` §1 이름. A·B 가 각자 유도한 앵커를 재계산한다.
2. 사례 2의 `Comparison` 대조 블록이 같은 이름 2회 import 라 컴파일 불가 — 별칭 import 로 고쳐 V2 를 통과시키고 독자에게 해법까지 준다.
3. 워커별 도입부 길이·절차 항목 밀도 통일.
