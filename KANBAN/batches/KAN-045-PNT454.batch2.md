# KAN-045-PNT454 배치2 — 사례 8종 병렬 집필 (워커 4)

카드: [KAN-045-PNT454.md](../cards/KAN-045-PNT454.md) · 범위 `S4` · `S5`
선행: [배치1](KAN-045-PNT454.batch1.md)

> **이 문서는 착수 전 계획이다.** 수행 내역은 카드 실행 문서의 「수행 내역」에 있다.

사용자가 **오케스트레이션 관점**을 골랐다. 이 배치가 그 선택이 실제로 값을 하는 유일한 자리다 — 배치 1은 폭 2, 배치 3은 단일 문서라 순차다.

## 1. 작업 패키지

work 둘(`S4`·`S5`)을 **사례 단위로 4워커에 나눈다.** work 경계와 워커 경계가 다르므로 아래 표가 그 매핑이다.

### WP1 · `S4` 사례 1~5 집필 — 워커 A · B (+ C 절반)

| 워커 | 사례 | 대상 패키지 |
|---|---|---|
| A | 1 앱에 컴포넌트를 얹는다 / 2 브랜드 색으로 갈아입힌다 | core · tokens · foundations |
| B | 3 완성된 룩을 골라 입힌다 / 4 **룩을 직접 만든다(UI)** | style-guide-catalog · core `StyleGuide` |
| C | 5 로직만 가져다 쓴다 | hooks |

**완료 기준**: 사례마다 `scratchpad/S4-case<n>.md` 에 (도입 2~3문장 · 번호 절차 · 코드 블록 · 「그다음」 링크)가 서고, **코드 블록의 모든 import 토큰이 `S1-facts.md` 의 export 목록에 있다.** 없는 토큰이 하나라도 있으면 그 WP는 미완이다.

### WP2 · `S5` 사례 6~8 집필 — 워커 C(나머지) · D

| 워커 | 사례 | 대상 패키지 |
|---|---|---|
| C | 6 다이어그램·인포그래픽을 그린다 | visualization(유형 87) · viz 카탈로그(30) |
| D | 7 **viz 룩을 직접 만든다** / 8 이 레포에 기여한다 | viz style guide 저작 · QUALITY_CHECKLIST |

**완료 기준**: 위와 같음. 더해 **사례 7은 대비(WCAG) 게이트와 매니페스트 등재까지** 절차에 포함한다 — 그 둘이 없으면 저작한 룩이 CI를 통과하지 못한다(카탈로그 저작 게이트 계약).

### 워커 공통 계약

네 워커가 같은 형식으로 쓰게 만드는 것이 이 배치의 성패다. 오케스트레이터가 **모든 워커 프롬프트에 아래를 그대로 넣는다.**

1. **입력은 셋뿐** — `S1-facts.md`(사실) · `S2-cases.md`(축) · 선정된 voice 요약. 레포를 다시 조사하지 않는다.
2. **출력 형식 고정** — `### 사례 N · <이름>` → 도입 → `1.`~`n.` 번호 절차 → 코드 블록 → `**그다음**` 한 줄.
3. **수치는 `S1-facts.md` 것만 쓴다.** 세지 않은 수를 적지 않는다.
4. **파일을 쓰지 않는다** — scratchpad 산출물 한 개만 낸다. README는 S6이 조립한다.

## 2. 의존과 순서

```
        ┌── 워커 A (사례 1·2) ──┐
배치1 ──┼── 워커 B (사례 3·4) ──┼──▶ (배치 3 · S6 조립)
        ├── 워커 C (사례 5·6) ──┤
        └── 워커 D (사례 7·8) ──┘
```

- 워커 넷은 **서로를 안 읽는다.** 사례 간 「그다음」 링크는 `S2-cases.md` 가 이미 정해 둔 값이라 워커가 협의할 것이 없다.
- 배치 3은 넷이 모두 끝나야 시작한다(조립은 전량을 본다).

## 3. 리스크

| 리스크 | 언제 터지나 | 대응 |
|---|---|---|
| **워커별 문체·절차 형식이 갈린다** | 이 배치의 주된 비용. 사용자가 이 리스크를 알고 선택했다 | 「워커 공통 계약」 4항을 프롬프트에 그대로 박는다. 그래도 남는 차이는 S6에서 통합 재작성으로 흡수하고, **그 재작성 분량을 수행 내역에 적는다**(다음 카드의 관점 선택 근거가 된다) |
| 동시 4워커가 세션 예산 절반을 넘는다 | 워커 산출물이 각 400줄을 넘을 때 | 워커 출력은 **scratchpad 파일**이고 오케스트레이터에게 올라오는 것은 경로 + 요약이다. 전문을 컨텍스트에 올리지 않는다 |
| 워커가 죽은 API로 스니펫을 쓴다 | 사례 4·7(저작)에서 특히 — 내부 타입을 부를 일이 많다 | 완료 기준에 import 대조를 박았다. 어긴 산출물은 반려하고 그 워커만 다시 돌린다 |
| 사례 4·7이 나머지보다 3배 무겁다 | 저작 절차는 preset 작성 + 게이트 + 등재라 단계가 많다 | B·D에 각각 하나씩만 배정했다(둘을 한 워커에 몰지 않는다) |

**되돌리기**: scratchpad 파일뿐이라 워커 단위로 버리고 다시 돌리면 된다. README는 아직 안 건드린다.
