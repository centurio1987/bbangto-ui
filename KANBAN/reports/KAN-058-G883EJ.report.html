전략

문제

@centurio1987/bbangto-ui-style-guide-catalog 에서 Showcase 하나만 가져와도 번들이 101,092B 다(esbuild 0.27.7, minify, react·@centurio1987/* 바깥, 2026-10-07 main dist 실측). 그중 76,517B 가 청크 하나에서 오고, 그 청크가 src/_showcaseCopy.generated.ts 한 파일이다. 51개 Showcase 의 확장 카피(메뉴·철학 카드·연락처·푸터 문구)를 한 객체 SHOWCASE_COPY_EXT 에 모아 둔 파일이다.

원인은 src/_showcase.tsx:3 이다. 모든 Showcase 를 만드는 makeShowcase 가 이 객체를 import 해서 세 번째 인자(displayName)로 자기 몫을 찾는다(_showcase.tsx:104). 그래서 Showcase 어느 것을 가져와도 51개 몫이 함께 따라온다. KAN-051 이 dist 를 파일 단위로 나눴지만 이 파일은 한 덩어리라 그대로 남았다(KAN-051 「범위 밖」).

접근

  1. 카피를 preset 파일마다 나눈다. src/_showcaseCopy/<preset 모듈 이름>.ts 51개를 만들고, 각 파일은 그 preset 몫 하나만 export const <모듈>CopyExt: ShowcaseCopyExt 로 낸다. 파일 이름이 src/<preset>.tsx 와 1:1 이라 짝을 눈으로 맞출 수 있다.
  2. 나누기는 손으로 하지 않는다. 지금 파일의 객체 리터럴을 JSON.parse 로 읽어 JSON.stringify(값, null, 2) 로 다시 쓰는 일회성 스크립트(작업 공간에만 두고 커밋하지 않는다)로 한다. 값이 한 글자도 바뀌지 않았다는 것은 아래 검증의 데이터 대조로 본다.
  3. makeShowcase 에 네 번째 인자 ext?: ShowcaseCopyExt 를 둔다. 병합 규칙({ ...copy, ...ext }, ext 가 이긴다)은 그대로 makeShowcase 한 곳에 둔다. SHOWCASE_COPY_EXT import 는 지운다.
  4. preset 51개는 자기 카피만 import 해서 넘긴다. makeShowcase(wrapperComponents, copy, 'XxxShowcase', xxxCopyExt). 이 수정도 같은 스크립트가 하고, 파일마다 호출이 정확히 하나 바뀌었는지 센다.
  5. SHOWCASE_COPY_EXT 공개 export 는 남긴다. src/_showcaseCopy/index.ts 가 51개를 모아 지금과 같은 키 순서의 객체를 만들고, src/index.ts 가 그것을 내보낸다. 카피 완비성 스토리(ShowcaseCopyCompleteness.stories.tsx)가 이 값을 읽는다. 이 모음 파일은 Showcase 쪽에서 아무도 import 하지 않으므로 Showcase 번들에 안 들어간다. 옛 _showcaseCopy.generated.ts 는 지운다(package.json exports 가 . 과 manifest 뿐이라 깊은 경로로 가져올 길이 없다).
  6. 상한을 새 실측으로 낮춘다. bundle-budget.json 의 sgc basis.representative 를 다시 재고, max 는 규칙대로 다시 계산한다. 추정은 약 26KB(101,092 − 76,517 + Neobrutalism 몫. Neobrutalism 몫은 UTF-8 801B 인데 esbuild 가 한글을 \uXXXX 로 내보내 더 커진다)이고 확인 안 함이다. all 은 다시 재서 상한 안이면 basis 를 그대로 둔다.

바뀌는 동작 (changeset 에 적는다)

  • makeShowcase(W, copy, 'NeobrutalismShowcase') 처럼 카탈로그의 displayName 을 넘기면 그 카탈로그 카피가 자동으로 붙던 동작이 없어진다. 확장 카피는 네 번째 인자로 넘기거나 copy 에 직접 넣는다(ShowcaseCopy 가 이미 그 필드를 optional 로 받는다). 카탈로그에 없는 이름을 넘기던 외부 저작자에게는 바뀌는 것이 없다 — 그때도 빈 카피였다.
  • SHOWCASE_COPY_EXT 객체를 고쳐 끼우면 makeShowcase 가 읽던 우회로도 함께 없어진다.
  • 변경 등급은 patch 로 둔다. 걷힌 동작을 쓰려면 카탈로그 preset 의 내부 이름을 넘기거나 공개 객체를 고쳐 끼워야 해서 정식 저작 경로 밖이고(README 저작 예시는 자기 이름을 쓴다, 확장 카피는 전에도 copy 에 직접 넣을 수 있었다), 이 기계에서 저장소 밖 사용처는 찾지 못했다. 이 기계 밖 사용처는 확인 안 함이다. KAN-051 의 patch 는 선례가 아니다 — 그 changeset 은 공개 동작이 그대로라고 적었고, 이번 카드는 README 가 적어 두었던 동작을 걷는다(검토 1항 검토자 의견, 2026-10-07).

버린 대안

  • 카피를 preset .tsx 의 const copy 에 합치기 — 파일은 덜 생기지만 생성 데이터와 손으로 쓴 코드가 한 파일에 섞인다. 카피를 다시 생성할 때 51개 코드 파일을 고쳐 써야 한다.
  • makeShowcase 가 동적 import() 로 몫을 가져오기 — 렌더가 비동기가 되어 Showcase 가 첫 화면에 빈 카피로 그려진다.
  • 생성기 스크립트를 저장소에 들이기 — 지금 파일을 만든 showcase-copy-generate 워크플로는 저장소에 없다(일회성). 카드 목적은 나누기이고, 다시 생성할 일이 생기면 그때 51개 파일 + 모음 파일 형태로 쓰면 된다. 배선이 어긋나면 아래 스토리 단언이 잡는다.
