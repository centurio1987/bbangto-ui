# KAN-046-33S4G8 — pnpm test:unit 을 CLAUDE.md 품질 게이트에 추가 — 매니페스트·대비·명명 게이트가 문서에 없다

## 전략
### 문제

루트 `package.json:10-11` 의 게이트 명령이 둘로 갈라져 있다.

```json
"test": "pnpm --filter storybook test",
"test:unit": "pnpm -r --filter=!storybook run test",
```

`pnpm test` 의 실체는 storybook 패키지 하나라 **패키지 vitest 는 `pnpm test:unit` 에서만 돈다.** 거기서만 도는 게이트가 넷이다 — 매니페스트 바이트 동기(style-guide-catalog·viz·viz-catalog·foundations), 대비 over-claim(`accessibilityAudit`), 명명 규칙, repo 전역 커버리지 census(`packages/foundations/src/metadataCoverage.test.ts`).

그런데 규범 문서 8곳(위반 그룹 13개)과 에이전트 훅 1곳이 게이트를 넷 또는 셋으로 적고 있다. 넷이 전부 초록인 상태로 올린 뒤 다른 사람이 `test:unit` 에서 처음 발견하는 경로가 열려 있다. `test:unit` 은 WAVE0 시점에 추가됐고(`WAVE0_REPORT.md:79`) README 는 KAN-045 에서 다섯을 적었지만 `CLAUDE.md` 에는 한 번도 들어온 적이 없다.

### 접근 — 문서 수정 + 강제 지점

문서만 고치면 다음에 게이트가 하나 더 늘 때 같은 드리프트가 같은 방식으로 재발한다. 이번이 그 재발 1회차다. 그래서 둘을 함께 한다.

1. **강제 지점** — `packages/foundations/src/gateDocs.ts`(순수 판정) + `gateDocs.test.ts`. 불변식은 **"`pnpm typecheck` 와 `pnpm test` 를 한 덩이에 함께 적은 명령 목록은 `pnpm test:unit` 도 적어야 한다"** 이고, 「한 덩이」 = `pnpm` 을 포함한 줄이 **서로 인접**해 이어진 그룹(빈 줄·코드펜스·`pnpm` 없는 줄이 경계).
2. **규범 13자리 일괄 수정** — 글로벌 지시문 「지적은 인스턴스가 아니라 클래스다」에 따라 전수 검색 → 일괄 수정 → 강제 지점에 박는다.

`CLAUDE.md` 규약대로 1번이 먼저다. 13자리가 아직 넷이라 red 로 뜨고, 2번을 마치면 green 이 된다.

### 왜 foundations 에 두는가

`packages/foundations/src/metadataCoverage.test.ts:1-8` 이 이미 같은 일을 한다 — 물리적으로 foundations 에 있지만 **repo 전역 거버넌스 게이트**이고, 그 주석이 근거를 적어 뒀다: "`test:unit` 의 `pnpm -r` 이 전 패키지를 항상 실행하므로 필터 누락 없음". `repoRoot = join(here,'..','..','..')` 와 `walk()` 스킵 패턴을 그대로 재사용한다.

배포물에는 안 실린다 — `package.json` 의 `files: ["dist", …]` 가 `src` 를 통째로 제외하고, 배럴(`src/index.ts`)·tsup 엔트리(`src/index.ts`·`src/meta/index.ts`) 어디에도 안 넣는다.

### 커버리지 한계 (의도적)

이 게이트가 잡는 것은 **리터럴 `pnpm typecheck` + `pnpm test` 동거 한 가지 표기**다. `pnpm --filter … test`, `pnpm typecheck/build/test`, `` `pnpm typecheck`/`build`/`test` `` 는 안 잡힌다. `gateDocs.ts` 주석에 이 한 문장을 박는다 — 전수를 보장한다고 오독되면 다음 사람이 안 볼 자리를 안 본다.

### 버린 대안

- **트리거를 `pnpm --filter storybook build` 로 확대** — 표기 변형에 강해지지만, 실제로 걸릴 후보(`ORDER.md:251`·`ASSET_INTEGRATION_PLAN.md:20`·`packages/visualization/PLAN.md:193`)가 전부 기록이거나 다른 패키지 필터라 넓혀도 잡을 대상이 없다. 오탐만 늘고 allowlist 가 다시 부푼다.
- **문서만 수정** — 재발을 못 막는다. 카드 목표("다른 사람이 test:unit 에서 처음 발견하는 일이 없어진다")를 문서 한 줄이 지지 못한다.
- **게이트 5종을 도는 CI 워크플로 신설** — `README.md:1226` 이 "게이트를 대신 돌려 주는 CI 는 없다"고 적었고 그것은 별개 결정이다.

### 범위 밖
