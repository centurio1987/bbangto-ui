# KAN-055-34A57K — 트리 셰이킹·글꼴·키보드 수정분 배포 (사용자 실행 지시 후)

## 전략
### 무엇을 하는가

KAN-051(번들)·052(글꼴)·053(Drawer·Tabs·Select 키보드)이 main에 병합된 뒤, 쌓인 changeset으로 버전을 올려 GitHub Packages에 배포한다. 외부 앱은 배포본만 설치할 수 있으므로 이 카드가 끝나야 외부 앱 쪽 문제가 실제로 풀린다.

### 승인 규칙

main push와 배포는 밖으로 나가는 일이라 **사용자의 분명한 실행 지시가 있어야 한다.** 그 지시가 나오기 전까지 이 카드는 백로그에 둔다. 카드를 할 일이나 진행 중으로 옮기는 일은 승인으로 보지 않는다.

`.github/workflows/release.yml:6-8`은 main push만으로 돈다. 그래서 push하는 순간 그동안 main에 쌓인 로컬 커밋(칸반 커밋 포함)이 함께 나가고, changeset이 남아 있으면 Version PR이 만들어진다. 이 사실을 지시를 받기 전에 사용자에게 알린다.

### 흐름

1. 쌓인 changeset을 읽어 패키지별로 올라갈 버전을 확인한다(core는 051 patch + 052·053 minor → minor 예상, 확인 안 함).
2. 지시를 받으면 main을 push → CI가 Version PR을 만든다 → PR 병합 → CI가 `pnpm build` 후 `pnpm run release`로 배포한다. KAN-051이 `release.yml`에 test:unit 단계를 넣었으므로 크기 상한을 넘으면 배포 전에 멈춘다.
3. 배포본 tarball을 받아 크기 게이트를 다시 돌린다. 로컬 dist가 아니라 배포된 파일로 확인하는 것이 요점이다.

### 겹침 처리

- KAN-051·052·053 뒤에 직렬로 선다(셋이 끝나야 배포에 의미가 있다).
- KAN-054와 용인(054의 changeset은 054 병합 뒤에만 들어온다). 054가 먼저 끝나면 함께 배포된다.

### 범위 밖

- 외부 앱 쪽 업그레이드와 그쪽 번들 재측정(다른 저장소)
- 외부 앱이 요청할 화면 조각 9개(목록을 받으면 따로 카드로 만든다)
