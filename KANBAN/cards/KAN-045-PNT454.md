# KAN-045-PNT454 — README는 이 레포를 설명하기에 정보가 많이 부족하다. 이 프로젝트를 활용 사례 별로 분류하고, 사례 별로 사용 방법을 자세한 절차로 서술해라. 서술 과정에서 authoring-kit skill을 이용해라.

## 전략
지시 원문은 `KANBAN.md` 카드의 `원문:` 블록에 있다(중복 보관하지 않음).

### 무엇이 문제인가 — 실측

현 README(174줄)는 **패키지 목록 + 설치 스니펫**이다. 지시가 지적한 셋이 실제로 없다.

- 패키지 8종이 표 한 줄씩으로만 소개되고, 어떤 상황에 무엇을 고르는지가 없다.
- style guide를 **구현**할 수 있다는 사례가 없다. `StyleGuideProvider` 사용 예 4줄이 전부다.
- style guide를 **저작**하는 방법(preset 작성 → 대비 게이트 → 매니페스트 등재)이 한 줄도 없다.

거기에 **수치 drift**가 겹친다(실측 대조 결과):

| README 기재 | 실측 | 출처 |
|---|---|---|
| style guide preset 24종 | **51종** | `packages/style-guide-catalog/catalog.manifest.json` |
| 브랜드 프리셋 74종 | **76종** | `packages/foundations/foundation.manifest.json` |
| viz 카탈로그 "Blueprint_Technical_01 등" | **30종** | `packages/visualization-style-guide-catalog/catalog.manifest.json` |
| viz 유형 축 언급 없음 | **87종** | `packages/visualization/type.manifest.json` |

지시의 목표가 "README만 보고 자기 사례에 맞는 패키지를 골라 style guide까지 구현"이므로, **틀린 수치는 그 자체로 목표 미달**이다. 그래서 이 카드는 문장 작업이 아니라 **매니페스트를 SSOT(single source of truth, 유일 정본)로 삼는 대조 작업**을 포함한다.

### 접근 — 사례 축을 먼저 세우고 절차를 매단다

축을 "패키지별"로 잡으면 지금 표와 같은 것이 길어질 뿐이다. **처음 온 사람이 자기를 알아보는 축**은 *무엇을 만들려는가*이므로, 사례를 그 축으로 가른다. 사례마다 ① 필요한 패키지 ② 설치 ③ 최소 동작 코드 ④ 그다음 단계를 **번호 절차**로 단다.

사례 후보(S2에서 확정):

1. 앱에 컴포넌트를 얹는다 — core + tokens
2. 브랜드 색으로 갈아입힌다 — foundations(76)
3. 완성된 룩을 골라 입힌다 — style-guide-catalog(51)
4. **룩을 직접 만든다** — style guide 저작 (지시가 콕 집은 자리)
5. 로직만 가져다 쓴다 — hooks
6. 다이어그램·인포그래픽을 그린다 — visualization(87 유형) + viz 카탈로그(30)
7. **viz 룩을 직접 만든다** — viz style guide 저작
8. 이 레포에 기여한다 — 품질 게이트

### 제약

- **README 한 장으로 자립한다.** 지시의 목표가 "README만 보고"다. 개념 심화는 `DESIGN_SYSTEM_GUIDE.md`(atom/molecule/block/pattern 기준표)가 이미 있으므로 **링크로 넘기고 복제하지 않는다**. 어디까지를 README에 담고 어디부터 링크로 넘길지는 검토의 판단 항목으로 낸다.
- **코드 스니펫은 실제 export를 쓴다.** 지금 README의 `foundationCatalog['coral']` 같은 표기가 살아있는 API인지 S1에서 대조하고, 죽었으면 고친다. 검증되지 않은 스니펫은 문서가 아니라 함정이다.
- **authoring-kit은 지시된 도구다.** 이 프로젝트에 미설치(`installed_plugins.json`에 bbangto-ui 없음)이나, 사용자 레지스트리 `~/.claude/authoring`은 살아 있고 voice 5종이 등록돼 있다. 플러그인 설치는 `~/.claude` 공유 상태 변경이라 **설치 없이** 마켓플레이스 경로의 스크립트를 `CLAUDE_PLUGIN_ROOT`로 직접 호출한다. spec은 이 프로젝트에 새로 등록한다(`.claude/authoring/specs/`).

### 버린 대안

- **docs/ 로 쪼개기** — 사례별 md를 따로 두고 README는 목차만. 지시의 "README만 보고"와 정면으로 어긋나고, KAN-044(문서 정리)가 세려는 문서 수를 늘린다.
- **자동 생성** — 매니페스트에서 README 표를 생성(KAN-025의 trendTable 선례). 수치 drift는 막지만 사례별 산문 절차는 생성 대상이 아니다. 이번 범위 밖이고, 필요하면 후속 카드로 낸다.
- **영문 README** — 지시에 없다. 기존 문체(한국어)를 유지한다.
